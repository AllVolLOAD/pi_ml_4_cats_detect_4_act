# Vision / ML Workflow: Инженерный подход

## 🎯 Цель визуального пайплайна в проекте

> Не «обучить модель», а **получить стабильную систему**, которая:
> * видит кота (детекция)
> * понимает, что он делает (инференс)
> * работает 24/7 без деградации

ML здесь — инструмент, не цель.

---

## ⚠️ Ключевое архитектурное решение

Проект **разделяется на два уровня ML**:

### Уровень A — Детекция (обязательный, база)

* **Детект:** `cat`
* **Инструмент:** YOLOv8 (pretrained + fine-tune при необходимости)
* **Результат:** стабильный bbox кота в кадре
* **Приоритет:** сначала это должно работать идеально

### Уровень B — Активность (опциональный, v2)

Есть **два варианта**, и это нужно зафиксировать:

#### Вариант B1 (рекомендуемый, быстрый) ⭐

**Правила + ROI**, без ML активности:

* детект кота (Уровень A)
* зоны: миска, поилка, игровая зона (ROI в кадре)
* логика по времени нахождения в зоне

**Плюсы:**
* минимум данных
* работает сразу
* легко отлаживать
* не требует обучения

**Минусы:**
* менее гибко
* нужно правильно задать зоны

**Пример логики активности (B1):**

* **eating:** bbox в зоне миски ≥ 3 сек
* **drinking:** bbox в зоне поилки ≥ 2 сек
* **sleeping:** неподвижность ≥ 60 сек
* **playing:** активное движение вне зон

Это превращает абстракцию в реализуемый код.

#### Вариант B2 (ML-классификация активности)

* классы: eating / drinking / playing / sleeping
* YOLO как детектор активности
* требует **много данных** (500+ качественных кадров минимум)

⚠️ **Важно**: в первой итерации делать **B1**, B2 — только после накопления данных.

## 🔄 Этап 1: Сбор данных

### ❌ Неправильно
> Записывать всё подряд, потом разметить

### ✅ Правильно
> Собирать **событийные фрагменты**

### Практика

* **Сегменты:** 30–60 сек — ок
* **Частота:** несколько сессий в день
* **Важно:** НЕ писать часами пустой кадр
* **Фокус:** моменты когда кот в кадре и активен

### ⚠️ Анти-паттерн

**Не делать:**
* писать видео «на всякий случай»
* надеяться, что потом "как-нибудь разметим"
* копить часы пустого фона

**Это приводит к:**
* мусорному датасету
* уставшей разметке
* плохой модели

**Почему это важно:** через месяц ты сам забудешь, почему так нельзя, а документ тебя остановит.

### Техническая правка

В `data_collector.py`:

* обеспечить **ключевые кадры** при сегментации
* иначе первые кадры сегмента могут быть битые
* Рекомендация: либо `-force_key_frames`, либо писать без перекодирования если уже H.264

### Команда

```powershell
cd catcam\pc
.\scripts\collect_data.ps1 -Duration 1800 -Segment 60
```

**Параметры:**
- `-Duration`: общая длительность (1800 = 30 минут)
- `-Segment`: длина сегмента (60 = 1 минута)
- Результат: `data/raw_videos/YYYYMMDD_HHMMSS_segment_NNN.mp4`

**Стратегия сбора:**
- Собирать в разное время (утро/день/вечер)
- Фокус на моментах активности кота
- Не записывать пустые кадры часами

## 🎨 Этап 2: Разметка

### ❌ Критическая ошибка

> "размечайте каждый 10-й кадр"

Это путь к:
* 90% одинаковых данных
* переобучению
* пустой трате времени

### ✅ Правильный принцип

**Размечать не кадры, а состояния**

**Рекомендованный подход:**
* из 1 минуты видео → **10–20 кадров**
* каждый кадр должен **отличаться по позе / положению / сцене**
* разрешён пропуск кадров без кота
* **не размечать «почти одинаковые» кадры**

### Правило разметки

**Если ты сомневаешься, размечать кадр или нет — не размечай.**

**Лучше:**
* меньше данных
* но уверенных и однозначных

**YOLO хуже переносит шум, чем нехватку данных.**

Это уберёт соблазн «ну вроде кот, давай размечу».

### Практика разметки

**Для Уровня A (детекция кота):**
- Размечать только bbox кота
- Класс: `cat`
- Минимум: 100-200 разнообразных кадров
- Фокус: разные позы, расстояния, освещение

**Для Уровня B2 (активность, если делаете):**
- Размечать bbox + класс активности
- Классы: eating, drinking, playing, sleeping
- Минимум: 500+ кадров (100+ на класс)
- Баланс классов важнее общего объёма

### Команда

```powershell
cd catcam\pc
.\scripts\annotate.ps1 -Video "..\data\raw_videos\20240101_120000_segment_001.mp4"
```

**Управление:**
- **Мышь:** рисуем bbox вокруг кота
- **1-4:** выбор класса (для B2: eating/drinking/playing/sleeping)
- **Space:** следующий кадр
- **S:** сохранить аннотации
- **Q:** выход

**Важно:**
- Размечайте **разнообразные** кадры, не каждый N-й
- Пропускайте одинаковые/похожие кадры
- Размечайте кадры где кот в разных позах/положениях

## 📦 Этап 3: Подготовка датасета

YOLO датасет должен быть **маленьким, но разнообразным**, а не большим и однотипным.

**Рекомендации:**
* 300 качественных кадров > 3000 мусорных
* баланс классов важнее общего объёма
* разнообразие важнее количества

### Команда

```powershell
cd catcam\pc
.\scripts\prepare_dataset.ps1
```

**Что делает:**
1. Читает все JSON из `data/annotations/`
2. Извлекает кадры с аннотациями
3. Конвертирует bbox в YOLO формат (нормализованные координаты)
4. Разделяет на train/val (80/20)
5. Создает `data.yaml` для YOLOv8

**Результат:** `data/dataset/`:
```
dataset/
├── images/
│   ├── train/
│   └── val/
├── labels/
│   ├── train/
│   └── val/
└── data.yaml
```

## 🎓 Этап 4: Обучение

### Реальность

* CPU обучение = долго, но работает
* первая модель = **техническая проверка**, а не финал
* не ожидайте идеальных результатов с первого раза

### Рекомендуемая стратегия

**1. Первая итерация (техническая проверка):**
```powershell
.\scripts\train_model.ps1 -Model n -Epochs 20 -Batch 4
```

Проверить:
* bbox стабилен?
* не детектит тени/миски?
* работает на разных кадрах?

**2. Улучшение (после проверки):**
* больше эпох (50-100)
* больше данных (если нужно)
* больше модель (s/m, если есть GPU)

### Когда остановиться

**Обучение можно считать успешным, если:**

* bbox стабилен на видео
* кот не "теряется" при поворотах
* нет детекта статичных объектов
* инференс укладывается в целевой FPS

**Если это достигнуто — не улучшайте модель просто потому что можно.**

Это защитит от бесконечного «а давай ещё 50 эпох».

### Команда

```powershell
cd catcam\pc

# Для ограниченных ресурсов (CPU)
.\scripts\train_model.ps1 -Model n -Epochs 50 -Batch 4

# Если есть GPU
.\scripts\train_model.ps1 -Model n -Epochs 100 -Batch 16
```

**Параметры:**
- `-Model`: n/s/m/l/x (n = nano, самый быстрый)
- `-Epochs`: количество эпох (20-30 для проверки, 50-200 для финала)
- `-Batch`: размер батча (CPU: 4-8, GPU 4GB: 8-16, GPU 8GB+: 16-32)

**Результат:** `data/models/cat_activity/weights/best.pt`

**Метрики:** После обучения смотрите `data/models/cat_activity/results.png`

## 🚀 Этап 5: Использование модели

### Поток данных (важно зафиксировать)

```
Pi (камера)
 → стрим (SRT)
 → PC (приём, receiver.py)
 → детекция (5–10 fps, ai_detector.py)
 → кэш bbox
 → стрим 25 fps (streamer.py)
 → Twitch
```

❗ **Инференс НЕ равен FPS стрима**

**Частота инференса (детекции):**

* **5 fps** — достаточно для данной задачи
* **10 fps** — комфортно
* **>10 fps** — бессмысленно для данной задачи (убивает производительность без выгоды)

AI работает на 5-10 fps, стрим идет на 25 fps. Это нормально и правильно.

**Не пытайтесь оптимизировать инференс до 25 fps** — это убьёт систему без реальной выгоды.

### Обновление config.yaml

```yaml
ai:
  model_path: "data/models/cat_activity/weights/best.pt"  # или yolov8n.pt для начала
  class_filter: ["cat"]  # для Уровня A
  # class_filter: ["eating", "drinking", "playing", "sleeping"]  # для Уровня B2
```

### Запуск

```powershell
cd catcam\pc
python main.py
```

## 🧠 Идентификация котов (v2, отдельная задача)

> **Определение конкретного кота — отдельная задача**

⚠️ **Не смешивать это с детекцией активности**

**Варианты:**
* ошейники / визуальные маркеры
* re-id модель (отдельный классификатор)
* отдельный классификатор по crop (по внешнему виду)

Это задача для будущего, не для первой итерации.

---

## 🧪 Итеративный цикл

**Правильная последовательность:**

1. ✅ **Детекция кота работает стабильно** (Уровень A)
   - bbox стабильный
   - нет ложных срабатываний
   - работает в разных условиях

2. ✅ **Логика активности (ROI) работает предсказуемо** (Уровень B1)
   - зоны заданы правильно
   - время нахождения считается корректно
   - логика активности понятна

3. ⏳ **ML активности** (Уровень B2, опционально)
   - только после накопления данных
   - только если ROI недостаточно

4. ⏳ **Идентификация котов** (v2)
   - отдельная задача
   - не смешивать с активностью

## 📊 Рекомендации по ресурсам

### На локальной машине (ограниченные ресурсы):

* **Сбор данных**: работает в реальном времени (Pi → PC)
* **Разметка**: требует только OpenCV (легко)
* **Подготовка датасета**: быстро, работает на CPU
* **Обучение**: 
  * CPU: медленно (часы/дни), но работает
  * GPU: рекомендуется для обучения

### Для Docker/сервера:

* Обучение можно делать на мощном сервере/GPU
* Сбор данных и разметка - на локальной машине
* Готовую модель копировать в Docker образ
