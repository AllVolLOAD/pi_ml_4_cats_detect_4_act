# 🚀 Vision Pipeline Quick Start (ROI-first стратегия)

## Стратегия: Уровень A (детекция) → Уровень B1 (ROI)

ML здесь — инструмент, не цель.

**Принцип:** Сначала стабильная детекция кота, потом логика активности через зоны (ROI), без ML классификации активности.

---

**Управление:**
- Мышь: bbox вокруг кота

## Этап 2: Активность через ROI (Уровень B1) ⭐

После того как детекция работает стабильно:

### Задать зоны в кадре

В будущем будет скрипт для задания ROI, пока можно:

1. Определить координаты зон в кадре (1280x720):
   - Миска (eating zone)
   - Поилка (drinking zone)
   - Игровая зона (playing zone)
   - Зона сна (sleeping zone)

2. Логика:
   - bbox кота пересекает зону → активность = зоне
   - Время нахождения в зоне → статистика

**Это будет реализовано в следующей итерации.**

**Пример логики:**
* eating: bbox в зоне миски ≥ 3 сек
* drinking: bbox в зоне поилки ≥ 2 сек
* sleeping: неподвижность ≥ 60 сек
* playing: активное движение вне зон

## 🧩 ROI Configuration & Activity Logic (B1)

Этот раздел фиксирует **контракт между детекцией и логикой активности**.

Без этого ROI быстро превращается в «магические if'ы».

### 🎯 Цель ROI-уровня

ROI-уровень отвечает только за одно:

> **Преобразовать bbox кота + время → понятную активность**

Он:
* не знает про нейросети
* не зависит от FPS стрима
* работает детерминированно

### 🗺️ ROI: формат конфигурации

**Файл: `config.yaml`**

```yaml
roi:
  frame_size: [1280, 720]
  intersection_threshold: 0.3  # IoA порог для пересечения bbox ↔ ROI

  zones:
    eating:
      rect: [100, 500, 400, 700]      # x1, y1, x2, y2
      min_time_sec: 3

    drinking:
      rect: [450, 500, 650, 700]
      min_time_sec: 2

    playing:
      rect: [0, 0, 1280, 450]
      min_time_sec: 1

    sleeping:
      rect: [800, 450, 1280, 720]
      min_time_sec: 60
      max_movement_px: 15  # максимальное смещение центра для sleeping
```

**Принципы:**
* координаты **в пикселях**
* прямоугольники осознанно перекрываются или нет — это допустимо
* логика разрешения конфликтов описывается отдельно

### 📐 Правила пересечения bbox ↔ ROI

**Определение пересечения:**

Используем **Intersection over Area (IoA)**, не IoU:

```
IoA = area(bbox ∩ roi) / area(bbox)
```

**Порог:**
* если ≥30% bbox кота находится в зоне → зона активна
* меньше → игнорируем

**Почему не IoU:**
ROI часто больше кота, IoU там бессмысленен.

### ⏱️ Временная логика (ключевой момент)

**Состояние зоны:**

Для каждой зоны ведётся:
```python
ZoneState:
  active_since: Optional[timestamp]
  accumulated_time: float
```

**Алгоритм (упрощённо):**

```
каждый AI-такт (5–10 fps):

1. bbox пересекает ROI?
   ├─ нет → сброс active_since
   └─ да:
       ├─ если active_since пуст → set now
       └─ accumulated_time += dt

2. accumulated_time >= min_time_sec?
   └─ активность подтверждена
```

⚠️ **Важно:** FPS стрима не участвует. Только таймстемпы AI-инференса.

### 🧠 Разрешение конфликтов зон

Если bbox пересекает **несколько зон одновременно**:

**Приоритет (по умолчанию):**

```
eating > drinking > sleeping > playing
```

**Почему:**
* миска и поилка — точечные зоны
* playing — зона «по остаточному принципу»

Этот приоритет **должен быть явно зафиксирован**, а не спрятан в коде.

### 💤 Детекция sleeping (особый случай)

Sleeping — не просто зона.

**Условия:**

```
1. bbox в зоне sleeping
2. центр bbox смещается < X пикселей (max_movement_px)
3. время >= min_time_sec (например, 60)
```

Если кот дёрнулся → таймер сбрасывается.

### 📊 Выходные события ROI-уровня

ROI-логика **не рисует**, **не стримит**, **не логирует красиво**.

Она возвращает события:

```python
ActivityEvent:
  type: "eating" | "drinking" | "playing" | "sleeping"
  start_ts: float
  duration_sec: float
```

Дальше:
* streamer решает, что рисовать
* logger решает, что писать
* ML здесь не участвует

### ✅ Критерий готовности ROI (B1)

ROI-уровень считается готовым, если:

* активность **детерминирована**
* одинаковый вход → одинаковый результат
* нет зависимости от FPS стрима
* таймеры работают стабильно ≥ 24 часов

Если это выполнено — **ML активности не нужен**.

### ⛔ Что НЕ делать на этом этапе

* ❌ обучать activity-классификатор
* ❌ подбирать пороги «на глаз» без логов
* ❌ мешать ROI и ML в одном модуле
* ❌ считать активность по одному кадру

### 🧭 Что дальше (после ROI)

Только после стабильной работы B1:

1. логировать события (CSV / JSON)
2. смотреть реальные паттерны
3. понять, **где ROI не хватает**
4. и только потом думать про B2 (ML activity)
